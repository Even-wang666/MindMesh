# 用户故事

1. 找到真实用户、目标和收益，用“作为…我希望…以便…”表达一个结果。
2. 用 INVEST 检查独立性、可协商性、价值、可估算性、小型化和可测试性。
3. 过大的故事按流程步骤、业务规则、成功/失败路径或数据变体拆成端到端薄切片。
4. 用 Given/When/Then 写可观察的验收标准，覆盖主路径、关键边界和至少一个失败路径。
5. 验收标准描述行为结果，而非界面像素或内部实现。
