# PR 8：Curated Teams

日期：2026-10-04。基线：PR 7 `0a8afcc`。本阶段结果仅保存本地。

## 目录与安装

Main 内置两份 curated manifest：Web 交付团队（前端、后端、API 测试）与工程审查团队（架构、代码审查、测试自动化）。成员引用 [Agency Agents](https://github.com/msitarzewski/agency-agents) 的来源路径，数组顺序就是初始 Space 成员顺序。manifest 的 SHA-256 是团队目录 revision；Agency commit 独立记录。清单没有命令、工具授权、远程 URL 或 workflow/DAG。

新增固定 `marketplace:installTeam` IPC，仅接受 key/revision。Main 校验参数长度、teams kind、mindmesh-curated 来源、内置 sourceId 和 manifest revision；Renderer 不能传入 persona、成员、权限或安装命令。已安装团队直接返回关联 Space，不需要联网，也不覆盖用户编辑。

新安装先通过 PR 7 catalog/cache 取得一个 Agency commit 的所有引用，读取并校验本地快照中的 persona、原文和 MIT 许可。缺失成员、损坏快照或混合 commit 在任何 DB 写入前拒绝；stale summary 与完整快照仍可安装。事务内没有下载或异步操作。

DB 使用一个 `BEGIN IMMEDIATE` 原子完成来源 Agent 复用/创建、Space 创建、成员写入及来源映射。单 Agent 安装和普通 Space 创建复用拆出的内部写入方法，避免事务嵌套。任意步骤失败整笔回滚，不补偿删除已有 Agent。并发重复安装在事务中重新检查来源唯一性。

Agent 按 `(source, sourceId)` 复用，用户编辑的名称、persona、模型、工具和技能原样保留；新成员沿用 PR 7 默认模型、`tools=[]`、`skills=[]` 与完整来源/许可。重名分别生成 Agent/Space 的 `(2)` 等后缀。Space 来源保存 manifest 和成员的实际来源 revision，复用较早版本的 Agent 时不会把最新下载 revision 冒充为其安装版本。

市场团队卡片支持安装、处理中、失败重试和「已安装 · 打开」。Installed 状态每次由 SQLite 来源映射派生；Open 刷新 Agent/Space 列表后进入现有协作空间。用户仍通过现有 `@成员` 机制选择参与者。普通创建/编辑只接受既有字段，不能伪造或覆盖 Space 来源。删除 Space 级联清除映射，保留成员 Agent；重新安装可复用它们。

## 数据迁移与回滚

schema 3 → 4 增加 `space_sources`：`space_id` 外键删除级联，`(source, source_id)` 唯一，保存 revision 和 manifest JSON。schema 0–2 也沿集中迁移顺序升级。旧 Agent 来源、Space、成员、消息、插件 desired state 与 generation 保留；Runtime schema 仍为 2，不改变 Runtime 身份或 Home。

迁移前通过 `VACUUM INTO` 保存 `<dbPath>.before-schema-3.sqlite`（更早版本使用其实际版本号），迁移在单事务完成，重复启动不覆盖备份。回滚先退出应用，保存完整 dataDir 和当前 schema 4 数据库，再恢复迁移前 schema 3 备份后切回 PR 7。PR 7 不接受 schema 4，不能只修改版本号。迁移后的新消息/成员不在旧备份中；保留新库供再次升级，不混用原库的 WAL/SHM，不删除 Runtime 文件。
