# 插件交付与 GitHub 导入

日期：2026-10-05。基线 `3d3f610`。用户要求兼容性检查不再成为使用步骤；开发阶段验证插件，安装包携带通过验证的插件，用户自行选择安装。同时允许像技能一样粘贴 GitHub 链接导入：自动验证，失败说明原因并终止，成功提示完成。

市场改为读取随包目录，不再读取公开上游目录或恢复旧的上游缓存。候选清单锁定 npm 确切版本、完整性和许可。`pnpm prepare:plugins` 使用真实 Windows Electron、随包 DSH/pnpm 执行完整 staging、配置/协议和 SDK 初始化，再对所有非空候选组合执行离线安装与 SDK 初始化。只有全部通过才生成目录、离线 store/cache 和许可证资源。直接调用 electron-builder 也必须通过 beforePack 检查，候选、运行版本、架构或组合验证不一致时拒绝打包。当前随包插件是 `dsh-http-tools@0.1.5`；试验过的 `dsh-file-memory@1.3.2` 无法导入，未纳入候选或用户目录。组合验证最多四个候选，即十五个非空组合；增加数量时需调整验证策略，不能绕过门槛。

用户浏览市场不请求 npm 元数据、不下载或运行候选插件。已安装插件始终可管理；随包插件一键安装，使用安装包携带的离线依赖，自动完成最终集合验证并原子提交。插件不预先启用，第三方代码仅在用户选择安装后执行。原有 frozen lockfile、脚本拒绝、peer/config/协议检查和 core 物理隔离保留。GitHub 导入与随包插件混合时，第三方依赖可能需要联网；只有随包集合可保证离线安装。

GitHub 导入复用技能的公开 HTTPS 仓库/目录解析、具体 commit 锁定、有界归档下载与解压、链接文件拒绝。检查 package.json、入口/bundle 文件、平台、Node 和必需 peer；拒绝要求安装/构建脚本的源仓库。源代码自身打成带 SHA-512 收据的本地归档，不以同名 npm 包替代 GitHub 内容。安装版本附加完整 commit 和仓库/目录身份摘要，便于在上游没有改版本号时区分不同内容，也防止同一 commit 的不同插件目录相互覆盖。完整集合启动验证成功才提交；更新已禁用插件也先单独激活候选验证，提交后保留禁用状态。取消/失败保持旧集合，错误原因显示在导入结果中，成功显示“验证通过，安装完成”。

固定 IPC 仅增加 GitHub URL/requestId 入口，没有任意 registry、文件路径或命令入口。正常界面移除手动兼容性按钮；显式 loopback fixture 和内部 check 保留开发回归能力。初始化验证证明这一版本能加载，不是第三方安全认证，也不保证上游联网服务始终可用。

验证记录：完整回归 34 个文件通过，309 项通过、3 项跳过；类型、格式与 lint 检查通过。开发版 Windows Electron 已通过 HTTP 插件完整 SDK 与离线完整集合验证；GitHub 实际 staging 回归覆盖 commit 源码安装、目录身份隔离、peer 拒绝、启动失败、取消和原集合保留。界面双轮验收通过 GitHub 错误反馈、弹窗布局、离线安装、重启保持和移除。规范与需求两路审查的发现已修复，复审无剩余问题。验证记录绑定主进程构建、依赖锁和候选清单的 SHA-256，过期记录会阻止打包。最终 NSIS 安装包已生成并在本机隔离目录安装成功；安装版在无外部 pnpm 环境通过双轮界面、GitHub 错误反馈、离线安装、真实 curl_parse 工具调用、重启、core 物理隔离以及禁用/启用/移除。包内主进程构建和插件目录与最终验证记录一致；585 个运行时依赖实例，必需缺失为 0。首次静默测试因临时目录超过安装器已有 49 字符限制返回 87，换成短目录后成功，未修改安装器。隔离安装已静默卸载通过，测试可执行文件已移除。所有改动保存在本地，未推送；本轮尚未触发新的远程 Windows CI。
